# 세션별 코디네이터 보드

Paseo에서 여러 프로젝트를 운영할 때, 내가 결정할 일과 각 세션의 진행 상황을 한 화면에서 봅니다. **내 결정** 카드에서 작업 세션에 답하거나, 여러 작업의 순서를 조정해 달라고 코디네이터에 요청할 수 있습니다.

## 설치

세션을 운영할 컴퓨터에 Paseo 0.16.2 이상을 준비하고 Paseo 설정의 Plugins에서 신뢰할 플러그인의 실행을 켭니다. GitHub 저장소를 직접 설치하려면 그 호스트에서 다음 명령을 실행하세요.

```sh
paseo plugin install git:devbrother2024/paseo-coordinator-board
```

`git:`는 Git 소스를 지정합니다. Paseo CLI에서 접두사 없는 `owner/slug`는 플러그인 레지스트리 항목을 찾는 형식입니다. 설치 상태는 `paseo plugin ls coordinator-board`로 확인합니다. [저장소](https://github.com/devbrother2024/paseo-coordinator-board) · [Paseo 플러그인 설치 안내](https://paseo.sh/docs/plugins)

ZIP으로 받았다면 세션을 실행할 컴퓨터에서 압축을 풉니다. `paseo-plugin.json`이 들어 있는 `coordinator-board` 폴더에서 `paseo plugin install .`을 실행한 뒤 그 폴더를 같은 위치에 보관하세요.

## 첫 화면과 관리 범위

1. Paseo 사이드바에서 **세션별 코디네이터 보드**를 엽니다. 제목 아래 호스트 이름을 확인하고 **다이제스트에서 관리할 프로젝트 선택**에서 원하는 프로젝트를 추가합니다. 보드는 열린 동안 30초마다 갱신됩니다.
2. 관리 대상을 바꾸려면 **설정 → 관리 프로젝트 변경**을 엽니다. 세션이 아직 없는 프로젝트도 선택할 수 있습니다.
3. 다른 프로젝트의 작업 세션 하나만 포함하려면 **설정 → 기존 세션을 프로젝트에 연결**을 엽니다. 이름이나 ID로 검색한 뒤 원래 프로젝트와 워크스페이스를 확인합니다. 이미 관리 중인 대상 프로젝트를 선택하고 **이 프로젝트에 연결**을 누릅니다.
4. 연결한 세션은 대상 다이제스트와 칸반에 한 번 표시됩니다. 대화, 작업 파일, 세션 ID는 원래 워크스페이스에 남습니다. **프로젝트 연결 해제**를 누르면 원래 프로젝트도 관리 중일 때는 그 프로젝트에 다시 표시됩니다. 원래 프로젝트가 관리 범위 밖이면 보드에서 사라집니다.

**설정 → 보드 언어**에서 **한국어** 또는 **English**를 선택할 수 있습니다. 언어는 이 기기에 저장되고, 세션에서 읽은 질문과 직접 쓴 답은 원문으로 표시됩니다. [English overview](OVERVIEW.md)

## 코디네이터에 첫 작업 맡기기

1. 다이제스트에 넣을 프로젝트를 고른 뒤 **추천 설정으로 시작**을 누릅니다. 기본 헌장을 가진 코디네이터 세션이 전용 워크스페이스에 생깁니다. 같은 요청을 다시 누르면 기존 세션을 재사용합니다. 이미 사용하던 세션은 **설정 → 기존 세션에서 코디네이터 지정**에서 연결합니다. 자동 생성에 필요한 Claude Code 또는 Codex 계정이 없으면 화면에 연결 안내가 나옵니다.
2. **코디네이터에게 맡길 일**에 “편집 프로젝트의 자막 검수 결과를 정리해 줘”처럼 입력하고 **코디네이터에 요청 보내기**를 누릅니다. 지정한 세션이 관리 중인 프로젝트와 워크스페이스, 기존 작업, 사용 가능한 모델을 확인한 뒤 작업자를 배정합니다. 작업 위치가 모호하면 코디네이터가 확인하도록 헌장에서 안내합니다. **코디네이터 세션 열기**에서 답을 읽습니다. **다이제스트 요청**을 누르면 그 세션에 현재 내 결정을 정리해 달라는 요청을 보냅니다.
3. 첫 작업은 추천값으로 맡길 수 있습니다. 코디네이터가 작업 난이도를 판단하고 현재 호스트에서 쓸 수 있는 모델을 고릅니다. 직접 정하고 싶을 때 보드 상단 **설정 → 모델 배정**을 엽니다. A(최상)부터 D(기본)까지 작업 난이도별로 우선 모델만 지정하거나 예비 후보와 추론 강도까지 저장할 수 있습니다. 예를 들어 C급은 Cursor의 Gemini를 먼저 쓰게 할 수 있습니다. **추천으로 복원**하면 그 등급은 다시 기본 규칙을 따릅니다. 필수 훅을 요구하는 일은 Claude Code·Codex에 맡깁니다. 실제 모델 사용료는 내 계정의 구독·과금 조건을 따릅니다.
4. M은 코디네이터 자체를 생성하거나 교체할 때 사용할 모델입니다. M 후보를 바꿔 저장해도 현재 세션은 계속 일합니다. 담당자를 바꾸려면 **설정**에서 **새 코디네이터로 교체…**를 열고 **새 세션으로 교체**를 누릅니다. 새 세션을 확인한 뒤 담당자를 전환하며, 카드의 질문과 판단·기존 작업자는 이어집니다.

처음 만든 운영 워크스페이스는 이 호스트의 Paseo 사이드바에 자동으로 고정됩니다. **설정 → 사이드바 고정**에서 자동 고정을 끌 수 있습니다. 같은 워크스페이스에서 세션을 교체하면 사용자가 정한 고정 상태가 유지됩니다. 이미 쓰던 코디네이터를 고정하려면 **현재 운영 워크스페이스 고정**을 누르세요.

처음 만들거나 교체할 코디네이터의 도구 권한은 버튼 위에서 확인합니다. 보드는 이 호스트가 제공하는 모드를 조회해 **Claude Code는 Auto mode**, **Codex는 Auto-review**를 우선 선택합니다. 우선 모드를 사용할 수 없으면 이 실행기가 제공하는 대체 권한 모드를 조회해 표시합니다. 이 두 실행기를 사용할 수 없으면 호스트에서 일반 작업 모드가 확인된 OpenCode(Build)나 Copilot(Agent)도 후보가 됩니다. 지원되는 모드를 확인할 수 없을 때는 실행기·모델을 새로 고치거나 Paseo MCP를 사용하는 기존 세션을 지정하세요. 다이제스트 요청은 지정된 코디네이터에 최신 질문과 결과를 정리하도록 요청합니다. 사실 질문 자동 답장이 켜져 있으면 코디네이터가 확인된 사실을 담당 세션에 전달할 수 있습니다. 자동 심사가 사람에게 돌려준 권한은 원래 세션에서 응답합니다. 이미 사용하는 세션의 모드는 Paseo의 세션 권한 메뉴에서 바꿀 수 있습니다.

작업 세션은 보드를 연 호스트에 생성됩니다. 코디네이터는 관리 프로젝트 안의 작업 위치에 새 세션을 만들 수 있습니다. 외부 프로젝트에서 연결한 세션은 지정된 그 세션만 관리 범위에 들어옵니다. 작업 요청·카드 답장·질문·다이제스트 전송과 작업자 실행에는 수신 세션의 모델 사용 조건이 적용됩니다. 보드 조회와 배정표 편집은 호스트의 목록과 설정을 사용합니다.

## Paseo에 연결한 실행기 사용하기

**설정 → Paseo 실행기**를 열면 보드가 현재 호스트의 Paseo에 실행기와 모델을 묻습니다. 새로 연결한 실행기는 기본으로 배정 후보에 포함됩니다. 설정을 열어 둔 채 다른 도구를 연결했다면 **실행기·모델 새로 고침**을 누르세요. 각 항목에서 Paseo에 등록한 이름과 ID, 선택 가능한 모델 수, 배정할 수 있는 작업 등급을 확인할 수 있습니다. 모델이 없는 경우와 모델 목록을 읽지 못한 경우도 구분해 표시합니다.

예를 들어 코디네이터가 Codex여도 C급 작업자는 Cursor의 Gemini나 이 호스트에 등록된 다른 ACP 실행기로 지정할 수 있습니다. **모델 배정**에서 등급을 고른 뒤 실행기별 필터로 모델을 둘러보거나 실행기·모델 이름과 ID를 검색하세요. 같은 모델 ID를 제공하는 두 실행기는 서로 다른 후보입니다. 선택한 등급에서 실제로 적용할 모델은 목록 맨 앞에 표시되며, 추천 또는 저장한 배정의 추론 강도까지 선택됩니다. Codex만 연결했다면 호스트의 Codex 모델에서 고릅니다. 연결된 Claude Code·Codex 모델이 없으면 일반 A·B 작업에도 다른 실행기의 모델을 추천합니다. 모델이 전혀 없으면 연결하거나 다시 포함할 실행기를 안내합니다. 저장한 우선순위가 있으면 사용 가능한 첫 후보를 씁니다. 저장한 후보를 모두 사용할 수 없을 때는 후보를 바꾸거나 **추천으로 복원**하세요.

특정 도구를 쉬게 하려면 해당 항목의 **배정에 포함됨**을 눌러 제외하세요. 이후 배정은 포함된 후보 중에서만 고릅니다. 저장해 둔 후보의 순서는 유지되므로 다시 포함하면 같은 우선순위를 사용할 수 있습니다. 칸반 카드는 기존 세션이 실제로 사용하는 실행기와 모델을 보여 줍니다.

## 다른 기기의 세션 찾아보기

**설정 → Paseo 호스트**에는 앱에 등록한 기기가 모두 표시됩니다. 새로 등록한 기기도 기본으로 포함합니다. 이름 아래에서 **세션 목록에 표시 중** 또는 **세션 목록에서 숨김**을 확인하고, 옆의 **숨기기** 또는 **표시하기**를 눌러 바꿉니다. 오프라인 기기는 연결 상태를 표시하고, 다시 연결되면 목록을 열 수 있습니다. 같은 설정 안의 **기기별 세션 찾아보기**에서 기기를 고르면 그때 해당 호스트에 세션 목록을 요청합니다. 이름이 같은 기기는 식별자를 확인하세요. 목록에서 제외한 기기는 보드를 다시 열어도 숨겨집니다. 이 설정은 호스트별 세션 목록에 적용됩니다. 작업 배정과 다이제스트는 보드를 연 호스트에서 진행됩니다.

### GitHub PR과 내 결정

사이드바의 숫자는 이 호스트에서 사람의 답을 기다리는 세션과 병합을 검토할 PR을 합한 값입니다. 관리 프로젝트에 GitHub 원격 저장소가 있으면 호스트의 GitHub CLI(`gh`)로 열린 PR을 조회합니다. 병합 조건을 충족한 PR은 **내 결정**에 뜹니다. **GitHub에서 병합 여부 검토**를 눌러 변경 사항을 보고 GitHub에서 결정하세요. 초안이나 검사 중인 PR은 **프로젝트별 진행**에서 볼 수 있습니다. 여러 프로젝트가 같은 저장소를 쓰면 내 결정에서는 PR 한 건으로 셉니다.

저장소를 자동으로 찾지 못했거나 다른 저장소를 보고 싶다면 **설정 → 프로젝트별 GitHub 저장소**에서 `owner/repository`를 입력하세요. **PR 조회 끄기**로 프로젝트별 조회를 끌 수 있습니다. 조회에 실패하면 보드를 연 호스트에서 `gh`의 설치와 저장소 접근 권한을 확인하세요.

## 내 환경에 맞게 고치기

ZIP에는 TypeScript 원본이 들어 있습니다. 기본 모델과 추론 강도는 보드에서 바꾸고, 기본 후보 선정 방식을 바꾸려면 `shared/dispatch.ts`를 확인하세요. 코디네이터에게 자동 적용되는 헌장은 `server/lifecycle.ts`, 배정 가능한 작업 공간을 조회하고 작업자에게 맡기는 도구는 `server/operations.ts`에 있습니다. 기존 세션에 자기 기준을 설명할 때는 [운영 예시](templates/coordinator-session.md)에서 공개·예산 변경처럼 직접 답할 일을 골라 적을 수 있습니다. 수정한 사본은 시험 호스트에서 다시 불러와 확인하세요.

## 보드 읽기

| 칸 | 들어오는 일 |
|---|---|
| 내 결정 | 실제 응답 대기, 세션이 대화에서 직접 청한 확인·선택, 카드에 기록한 질문이 있는 세션입니다. 카드에서 질문, 선택지와 수신자를 확인합니다. |
| 진행 중 | 세션이 작업하고 있습니다. |
| 확인 대기 | 오류·새 결과를 살펴보거나 보고된 근거를 확인할 차례입니다. |
| 대기 중 | 대화가 쉬고 있습니다. 작업 결과는 아직 검증할 수 있습니다. |
| 완료 | 사람이 결과를 확인하고 카드에 완료 근거를 남겼습니다. 새 권한 요청이나 작업이 생기면 그 신호가 우선합니다. |
| 미확인 | 세션 초기화 중이거나 상태를 판정할 정보가 부족합니다. |

### 결정 카드에서 답하거나 조율 요청하기

모든 세션 결정 카드에서 제목 아래의 **담당 세션 열기**를 눌러 원문 대화를 확인할 수 있습니다. PR 카드에는 GitHub 링크와 지정된 코디네이터 세션으로 가는 버튼이 있습니다.

**내 결정**에서 먼저 결정할 질문 한 줄과 추천 답장을 읽으세요. 추천이 있으면 **추천 답장 보내기**로 화면에 적힌 문장을 담당 세션에 전달합니다. 필수 정보가 빠졌다면 카드에 무엇을 알려줘야 하는지 표시됩니다. 예전에 만든 카드에서 **코디네이터에 추천 요청**을 누르면 그 질문 하나의 근거를 다시 검토합니다. 질문·조율·세션 열기는 **다른 방법**, 원문과 추천 이유는 **근거 보기**에서 확인할 수 있습니다.

예를 들어 작업자가 “이 세션의 원래 프로젝트가 어디인가요?”라고 묻는다면 보드가 확인할 수 있는 사실입니다. **다이제스트 요청**을 누르면 지정된 코디네이터가 해당 세션에 프로젝트 정보를 보내고, **프로젝트별 진행**에 처리 기록을 남깁니다. 자동 답장은 호스트마다 기본으로 켜져 있으며 **설정 → 사실 질문 자동 답장**에서 끌 수 있습니다. 답장을 받은 세션이 모델을 실행하면 해당 제공자의 사용량에 반영될 수 있습니다. “작업 폴더를 지울까요?”처럼 사람의 판단이나 권한이 필요한 질문은 **내 결정**에서 검토합니다.

| 하려는 일 | 카드에서 누를 항목 | 받는 곳 |
|---|---|---|
| 추천대로 답하거나 선택지 고르기 | **추천 답장 보내기**, 또는 선택지를 고른 뒤 **선택한 답장 보내기** | 담당 작업 세션 |
| 내용을 고쳐 답하거나 직접 쓰기 | **고쳐 보내기** 또는 **직접 답장** → **담당 세션에 답장 보내기** | 담당 작업 세션 |
| 결정 전에 한 가지 더 묻기 | **질문하기** → **담당 세션에 질문 보내기** | 담당 작업 세션 |
| 다른 일과 우선순위·역할 조율하기 | **코디네이터에 조율 요청** → **코디네이터에 조율 요청 보내기** | 지정된 코디네이터 세션 |
| Paseo의 도구 권한·플랜 승인 요청 처리하기 | **담당 세션 열기** → Paseo의 승인 화면에서 응답 | 요청이 열린 원래 세션 |

보내기 전에 **받는 곳**과 문장을 확인하세요. 현재 세션의 대화 근거와 카드 상태가 바뀌면 보드를 새로 고친 뒤 응답합니다. 직접 보낸 답장은 결과를 기다리는 **확인 대기**에 반영됩니다. 질문이나 조율 요청을 보냈을 때는 결정이 남아 있을 수 있습니다. 결과를 확인한 다음 **기록 추가** 또는 **기록 편집**에서 완료 근거를 남기세요.

## 대화에서 사람 차례를 찾는 방법

보드는 선택한 프로젝트 안에서 응답이 끝난 세션의 최근 타임라인을 읽습니다. 최대 48개 항목에서 사용자·에이전트의 최근 대화 4개만 발췌하며, 발화마다 마지막 2,000자까지 사용합니다. 기본 분류는 “확인해 주실 것”, “어느 쪽으로 할까요?” 같은 한국어·영어 표현을 살펴보고 질문과 선택지를 표시합니다. 변화가 없는 발췌는 짧게 재사용합니다. 닫힌 세션은 보드가 다시 띄우지 않습니다.

기존 세션을 쓸 때는 **설정 → 기존 세션에서 코디네이터 지정**으로 들어가 관리 중인 세션을 고릅니다. 다음 대화용 실행 때 Paseo MCP가 연결된 코디네이터에 `read_board_conversation`과 `classify_board_conversation`이 붙습니다. 첫 도구는 관리 세션 목록이나 해당 세션의 최근 발췌를 읽고, 둘째 도구는 현재 발췌 ID에 질문·검토·대기 판단을 기록합니다. 새 작업을 위임받으면 `plan_board_assignment`로 관리 프로젝트, 세션, 워크스페이스와 모델 후보를 확인하고 `assign_board_worker`로 작업자를 생성합니다. 이미 열려 있는 세션이라면 턴이 끝난 뒤 해당 세션만 다시 불러오세요. 시험 호스트에서는 `paseo agent reload <세션 ID>` 후 코디네이터 도구가 나타났습니다. 코디네이터에게 [첫 요청](templates/coordinator-session.md)을 보내면 관리 세션을 살피고, 발췌와 기존 지시를 대조해 질문·확인 대기·대기로 분류할 수 있습니다. 새 발화가 들어오면 이전 발췌에 대한 판단은 다시 적용되지 않습니다. 이미 보드에 적은 사람의 질문은 기록 편집에서 직접 정리할 수 있습니다. 보드를 여는 동작 자체가 코디네이터를 실행하지는 않습니다.

## 내 세션에서 질문을 올리기

보드 조회와 직접 기록은 설치 직후 사용할 수 있습니다. 세션의 자동 보고에는 Paseo MCP를 지원하는 실행기와 호스트의 도구 연결이 필요합니다. Paseo 0.16.2의 설정 이름은 `daemon.mcp.enabled`와 `daemon.mcp.injectIntoAgents`입니다. 뒤의 설정은 호스트의 에이전트에 제공하는 Paseo 도구 전반에 적용됩니다. 제공 범위를 확인하고 사용 여부를 선택하세요. [Paseo MCP 설정](https://paseo.sh/docs/mcp)

1. 보고받을 세션 카드의 **기록 추가** 또는 **기록 편집**에서 **보드 보고 켜기**를 누릅니다.
2. 그 세션이 다음에 대화용으로 열리면 지원하는 실행기에 `report_to_board` 도구가 제공됩니다. 이미 실행 중인 턴은 그대로 진행됩니다. 선택한 코디네이터 세션에는 [설계·운영 시작 문장](templates/coordinator-session.md)을 자기 기준에 맞춰 붙여 넣을 수 있습니다.
3. 그 세션이 질문을 올리면 **내 결정**, 확인할 결과를 올리면 카드에 **세션 보고**가 표시됩니다. 도구는 자기 카드에만 쓸 수 있습니다. 사용자가 남긴 기록은 사용자가 직접 편집하거나 해제합니다.

## 로컬 데이터와 제거

보드는 선택한 호스트에서 Paseo SDK로 세션·워크스페이스 목록을 조회합니다. 보드 조회는 모델을 호출하지 않습니다. 보고를 켠 세션의 실행기가 모델을 사용할 때는 해당 제공자 설정이 적용됩니다. 선택한 프로젝트의 대화 발췌는 호스트 메모리에 잠시 유지됩니다. 지정한 코디네이터가 발췌 도구를 호출할 때는 해당 모델의 대화 맥락으로 전달됩니다. 관리 범위, 세션 연결, 코디네이터의 판단 요약, 중복 전송 확인용 영수증은 호스트의 Paseo 홈 아래 `plugin-data/coordinator-board/scope.json`에 저장됩니다. 직접 적은 질문과 근거는 그 호스트의 Paseo 홈 아래 `plugin-data/coordinator-board/notes.json`에 저장합니다. 설치 디렉터리와 분리되어 업데이트 뒤에도 보존됩니다.

질문과 근거 원문은 로컬 JSON에 평문으로 보관됩니다. 설치한 호스트에서 `paseo plugin ls coordinator-board`로 상태를 확인합니다. 잠시 끄려면 `paseo plugin disable coordinator-board`, 다시 켜려면 `paseo plugin enable coordinator-board`를 실행합니다. 설치 등록을 지우려면 `paseo plugin remove coordinator-board`를 실행하고 `paseo plugin ls`에서 목록을 확인합니다. 다른 호스트를 대상으로 할 때는 각 명령 끝에 `--host 호스트주소:포트`를 붙이세요. 디렉터리 설치의 원본 폴더는 별도로 보관됩니다. 직접 남긴 기록까지 지우려면 해당 호스트에서 보관할 기록을 먼저 확인하세요. 이 패키지는 MIT 라이선스로 배포합니다.
